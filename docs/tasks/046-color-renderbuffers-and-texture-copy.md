# WebGL1 color renderbuffers and framebuffer-to-texture copies

Build on tasks 043–045. The integrating owner handles the facade, both cores, shared resource and Wasm transport, BrowserHost, and the three-path and original conformance fixtures. The authoritative requirements are pinned WebGL1 texture copies, read-operation clipping and feedback, plus GLES 2.0.25 sections 3.7.2 and 4.4.3.

1. Add RGBA4, RGB5_A1 and RGB565 renderbuffer storage and COLOR_ATTACHMENT0. Track attachment kind, format and generation, apply the existing retained-reference rules, and expose component sizes for the actual storage. Keep opaque RGB semantics through drawing, readback and copies. Use shared GPU color storage and the existing in-flight retirement policy.
2. Implement the WebIDL entry points and both cores' validation for copyTexImage2D and copyTexSubImage2D. Validate the source color channels and framebuffer status, reject exact-image feedback, apply WebGL clipping, and keep destination changes atomic on validation failure. A definition initializes uncovered texels, and a subimage retains uncovered texels and its existing image format/type.
3. Transport the source target snapshot, destination generation, coordinates and format in GL call order. Encode GPU copies before the next call can change the source. Reuse canonical storage and preserve packed destination conversion. Version the resource transport, with ABI4 and readback/DOM capabilities retained.
4. Run pinned tex-input-validation and adjacent framebuffer, mipmap and feedback originals through all three backends. Add shared Chrome assertions for color-buffer identity, resize, ordered positive/default source copies, clipping, format compatibility, and feedback. Run pnpm check, pnpm rust:build, pnpm rust:test:wasm, REFRAL_HEADLESS=1 pnpm test:chrome, pnpm build and REFRAL_HEADLESS=1 pnpm test:dist. Record per-core support and deliver through required CI and rebase merge.

## Acceptance

Both cores accept RGBA4, RGB5_A1 and RGB565 color renderbuffers and ordered texture copies. The color backing uses RGBA8 storage, with implicit opaque alpha for RGB565. New copy destinations initialize the region outside the source intersection. Subimage copies preserve the existing content there. Source attachment reallocation or deletion after the copy preserves results already encoded. [Storage and transport decision](../adr/013-framebuffer-color-copies.md)

The shared headless Chrome scene passes 21 assertions per backend and has exact native/JS/Rust pixel agreement. It checks initial RGB and RGBA storage, color/depth pairing, framebuffer clipping with negative source coordinates, two queued draws around a subimage copy, framebuffer validation, retained deletion, rejection of texture feedback and copies into a CubeMap face. The JSON plus images are under `artifacts/rtt/fbo-color-renderbuffer-copy`.

Headless Chrome 158.0.8127.36 with Apple Metal 3 ran 42 original WebGL1 files. Native passed 42, and each Refral core passed 41. The original tex-input-validation and copy-tex-image-and-sub-image-2d pass 63 and 503 assertions per backend respectively. Copy format coverage reports 51 native and 42 per Refral core because the upstream script conditionally exercises the RGB texture attachment branch. The framebuffer-object-attachment original remains unsupported at the stencil and packed depth-stencil paths. Raw results are under `artifacts/framebuffer-texture-copy/official-final`.

The local gates passed TypeScript, 226 JS unit tests, 58 tool tests, 75 native Rust tests, 47 actual-Wasm tests, 135 headless Chrome regressions and built deployment with ABI4/resource6/readback1/DOM upload2. Reproduce the original acceptance with `pnpm conformance:run --backend all --include '(tex-input-validation|copy-tex-image-and-sub-image-2d|copy-tex-image-2d-formats)\.html$' --output artifacts/framebuffer-texture-copy/reproduction`.
