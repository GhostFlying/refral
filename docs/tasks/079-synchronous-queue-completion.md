# Synchronous completion of submitted GL work

## Plan and scope

The pinned conformance/misc/uninitialized-test.html calls finish after allocations, uploads, resource deletions, draws and clears. WebGL1 inherits GLES 2.0.25 §5.1. A conforming synchronous finish returns after the effects of all earlier GL commands are complete. A successful synchronous readback from one framebuffer establishes its observed pixels. The distinction matters for work on unrelated buffers, textures, FBOs and previously deleted resources.

- Examine the current host's submission, synchronous Canvas2D readback, deferred destruction and the WebGPU queue completion primitive. Probe an unchanged native/JS/Rust original to identify the first affected call.
- Build an isolated, rerunnable Window and dedicated Worker probe with an independent WebGPU workload, an output-dependent readback, a separate Canvas2D sentinel readback and an actual asynchronous queue fence. Check bytes in both reads and compare wall-clock intervals with GPU timestamp-query when available. Keep raw per-trial measurements, feature availability and environment.
- Use headless Chrome, one worker and the shared GPU lock. Accept a synchronous implementation only with a verified completion boundary for all earlier commands. Document the remaining prerequisite if the existing bridge can only demonstrate a specific resource's visibility. Keep the asynchronous context factory and synchronous public GL calls.

The dependency experiment joins every value of a small GL-like workload: two separate buffer slices and two independently supplied texture pixels. A further draw reads its inputs and executes fragments with all color writes disabled and no depth/stencil attachment. An independent occlusion query observes that draw. Compare the GPU count to a CPU reference and check whether the joined resource bytes depend on the draw. This separates actual data dependencies from backend submission ordering.

## Specification and observed behavior

WebGL1 delegates finish to GLES 2.0.25 §5.1, covering earlier client, server and framebuffer effects. WebGPU's canvas snapshot waits for writes to the canvas's current texture. Its explicit queue-wide completion operation returns a Promise to the creating agent. The same agent needs to resume its event loop to consume that result. Prior work in ADR 007 tested blocking a worker which owns its GPU callback. [Pinned WebGL1 finish](https://github.com/KhronosGroup/WebGL/blob/39443210f7f81db4773eb104facadfb85d05dfa4/specs/latest/1.0/index.html#L3492), [GLES2](https://registry.khronos.org/OpenGL/specs/es/2.0/es_full_spec_2.0.pdf), [WebGPU canvas snapshot](https://www.w3.org/TR/2026/CRD-webgpu-20260915/#get-a-copy-of-the-image-contents-of-a-context), [onSubmittedWorkDone](https://www.w3.org/TR/2026/CRD-webgpu-20260915/#dom-gpuqueue-onsubmittedworkdone), [agent placement experiment](../adr/007-synchronous-readback.md)

Run the optional probe with `node tools/probe-queue-completion.mjs artifacts/conformance/campaign/queue-completion/final`. On 2026-11-18 the installed headless Chrome 158.0.8127.36 used an Apple metal-3 adapter in an unisolated Window and DedicatedWorker. Each realm executed 36 trials with three workload sizes and rotated paths. The heavy workload was an independent 256×256 render with 32,768 integer iterations per fragment. At this size the separate-texture path took 7.1–7.4 ms synchronously in Window and 7.4–7.9 ms in Worker. Its GPU pass took 6.29–6.75 ms and 6.75–7.08 ms respectively. Observing the prior queue fence added at most 0.1 ms after that return. These times include submission and bridge overhead. The queue fence callback also requires a task turn. Raw pixels, GPU times, wall times and controls are in `artifacts/conformance/campaign/queue-completion/final/{window,worker}.json`.

The dependency probe combined all four buffer words, every uploaded texture channel and all 128×128 framebuffer pixels. With all color writes masked and no depth or stencil target, adding a draw gave the same joined bytes [126,121,122,73]. The independent occlusion query changed from zero to one in both realms. A CPU evaluation counted 4,161 passing samples, while WebGPU reports a binary result on this adapter. Even a complete scan of GL-visible resources has no data dependency on that draw's execution. Retaining deleted generations, adding copy/sample usages for each mip, layer, depth/stencil aspect and buffer range, or folding query booleans into a marker still leaves the queue-wide completion contract unresolved. [WebGPU occlusion semantics](https://www.w3.org/TR/2026/CRD-webgpu-20260915/#occlusion)

## Audited Chromium path

Chrome 158.0.8127.36 pins Dawn `6e24542436a3ef58d4a1110f01712da9afbff3e3`. Blink's snapshot creates a new shared image and submits the copy on the same device queue. On the IOSurface/Metal path the destination end-access exports the queue's shared Metal event with the texture's latest use serial. Dawn signals that event with the pending submission serial after encoding its commands. Chromium records the event for consumers of that IOSurface to wait on. This accounts for the physical wait observed here. Other shared-image paths need their own guarantees. Chromium exposes its backend field only with developer features enabled, and the default adapter returned no backend field in either realm. The page has no standard capability for the shared-event guarantee. [Chromium Dawn pin](https://github.com/chromium/chromium/blob/158.0.8127.36/DEPS), [Blink snapshot](https://github.com/chromium/chromium/blob/158.0.8127.36/third_party/blink/renderer/modules/webgpu/gpu_canvas_context.cc#L1050), [Chromium IOSurface end access](https://github.com/chromium/chromium/blob/158.0.8127.36/gpu/command_buffer/service/shared_image/iosurface_image_backing.mm#L864), [Dawn Metal end access](https://dawn.googlesource.com/dawn/+/6e24542436a3ef58d4a1110f01712da9afbff3e3/src/dawn/native/metal/SharedTextureMemoryMTL.mm#235), [Dawn queue signal](https://dawn.googlesource.com/dawn/+/6e24542436a3ef58d4a1110f01712da9afbff3e3/src/dawn/native/metal/QueueMTL.mm#332), [Metal event ordering](https://developer.apple.com/documentation/metal/about-synchronization-events), [adapter IDL](https://github.com/chromium/chromium/blob/158.0.8127.36/third_party/blink/renderer/modules/webgpu/gpu_adapter_info.idl)

The original uninitialized-test completed 39 assertions on native. Before the host change, JS and Rust each reached one pass, then reported unsupported at finish and failed the original parse sentinel. The adjacent quickCheckAPI-D_G page reported one aggregate failure on each core, which does not localize a finish dependency. quickCheckAPI-L_S passed on all three. Evidence and screenshots are in `artifacts/conformance/campaign/queue-completion/originals`. Reproduce the three routes with `pnpm conformance:run --backend all --include 'uninitialized-test|quickCheckAPI-(D_G|L_S)' --screenshots --output artifacts/conformance/finish-baseline`.

## Idle queue implementation plan

Add an explicit synchronous finish operation to the common host contract and dispatch it from each live core. The browser host submits pending encoders, including presentation, and tracks the work issued by this context: queue buffer writes, external copies, submitted command buffers and browser-initiated canvas snapshots. Observe a real queue completion promise for each distinct batch. An untouched context or a context with a fulfilled fence covering its latest work can return synchronously. An outstanding epoch reports an explicit library diagnostic. Repeated flushes reuse the same fence; older callbacks must never certify a newer epoch. Verify both real cores on headless Chrome before and after submission, readback and confirmed drain. Re-run the unchanged original with call site evidence.
