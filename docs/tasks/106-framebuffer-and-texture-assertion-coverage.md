### Context attributes and readPixels

**50.** The original creates one default context and all 16 alpha/stencil/depth/antialias combinations. On all three backends, the observed alpha, stencil and depth match all 16 requests. Chrome grants all eight antialias=true requests. Refral exposes single-sample default buffers in every case. WebGL1 allows best-effort antialiasing. On each of 16 default and 16 user framebuffers, the test checks the fully covered and uncovered pixels and samples a diagonal edge. Each actually antialiased edge contributes two individual comparisons with 0 and 255. An aliased edge contributes one comparison. The captured 32 draw groups gave 24 aliased and 8 sampled edges on Chrome, and 32 aliased edges on each Refral core. All 16 user framebuffers ran the drawing group, and the depth/stencil fallback assertion never ran. The total is five outer assertions, 31 per combination, 24 checks for the false stencil/depth/antialias requests, and one extra per actually antialiased edge. This confirms the rendering branch for every reported attribute. Multisampled default rendering remains an optional capability gap. [Original context creation and framebuffer probe](https://github.com/KhronosGroup/WebGL/blob/39443210f7f81db4773eb104facadfb85d05dfa4/sdk/tests/conformance/context/context-attributes-alpha-depth-stencil-antialias.html#L76-L121) · [Edge pixels and combination loop](https://github.com/KhronosGroup/WebGL/blob/39443210f7f81db4773eb104facadfb85d05dfa4/sdk/tests/conformance/context/context-attributes-alpha-depth-stencil-antialias.html#L145-L273) · [WebGL1 drawing buffer](https://github.com/KhronosGroup/WebGL/blob/39443210f7f81db4773eb104facadfb85d05dfa4/specs/latest/1.0/index.html#THE_DRAWING_BUFFER)

**625.** The two contexts request antialias=false and true. Per context there are seven initial validations, 29 assertions for seven 2×2 reads and their final error, 15 invalid enum/type checks, three packed format/type combinations, five formats for each of seven basic types, four assertions for sustained drawing/readback, and six for Uint8ClampedArray and ordinary ArrayBuffer destinations. These contribute 99 per context plus one final parsing assertion per file. Chrome advertises OES_texture_half_float and its HALF_FLOAT_OES adds five format/type checks per context. Neither Refral profile exposes the extension. All three observed implementation read pairs were RGBA and UNSIGNED_BYTE. The five extra comparisons therefore check the permitted errors when reading the default buffer with HALF_FLOAT_OES. Two extra SharedArrayBuffer constructor checks per context are conditional on the environment. The ordinary campaign runs without cross-origin-isolation headers, which are reserved for the benchmark server. The totals equal the complete WebGL1 paths, including the three color results following 301, 302 and 303 draws in each context. ### Framebuffer completeness and missing color

**627.** The successful assertion sequences verify all three mandatory RGBA texture combinations on every backend. A later 16×16 framebuffer has only a depth attachment. Chrome finds it complete and checks NO_ERROR before, and INVALID_OPERATION after, readPixels, copyTexImage2D and copyTexSubImage2D. Refral requires a color attachment for a complete framebuffer. Its depth-only framebuffer is incomplete, so the original switches to a combined depth/stencil-only renderbuffer. It records its creation and setup and exits this helper after that framebuffer also proves incomplete. Later assertions in the file still run. These are exactly six native-only and two Refral-only messages. Depth-only and combined-depth/stencil-only framebuffers are outside the required WebGL1 combinations. Refral thus lacks the six checks conditional on a complete framebuffer with absent color. [Required combinations](https://github.com/KhronosGroup/WebGL/blob/39443210f7f81db4773eb104facadfb85d05dfa4/specs/latest/1.0/index.html#FBO_ATTACHMENTS) · [Original required checks](https://github.com/KhronosGroup/WebGL/blob/39443210f7f81db4773eb104facadfb85d05dfa4/sdk/tests/conformance/renderbuffers/framebuffer-object-attachment.html#L237-L285) · [Missing-color fallback and reads](https://github.com/KhronosGroup/WebGL/blob/39443210f7f81db4773eb104facadfb85d05dfa4/sdk/tests/conformance/renderbuffers/framebuffer-object-attachment.html#L585-L635)

The comparison also found **18 differently worded passing assertions**. WebGL requires FRAMEBUFFER_UNSUPPORTED for conflicting auxiliary attachments. At 2×2, where the conflict is the only violated condition, all six calls returned FRAMEBUFFER_UNSUPPORTED on all three backends. With a zero width or height, the attachments are also incomplete. GLES 2.0 §4.4.5 permits the implementation to choose which violated completeness condition to report. For exactly the three size pairs 0×0, 0×2 and 2×0, the original accepts either error status on the six conflict calls. Native returned FRAMEBUFFER_UNSUPPORTED in all 18, JS and Rust returned FRAMEBUFFER_INCOMPLETE_ATTACHMENT in all 18. All other successful messages match once the six-versus-two missing-color branch is accounted for. The manifest and upstream test stay unchanged. [Conflicting attachment and zero-size predicates](https://github.com/KhronosGroup/WebGL/blob/39443210f7f81db4773eb104facadfb85d05dfa4/sdk/tests/conformance/renderbuffers/framebuffer-object-attachment.html#L314-L353) · [WebGL1 attachment conflict rule](https://github.com/KhronosGroup/WebGL/blob/39443210f7f81db4773eb104facadfb85d05dfa4/specs/latest/1.0/index.html#FBO_ATTACHMENTS) · [GLES 2.0.25 framebuffer completeness](https://registry.khronos.org/OpenGL/specs/es/2.0/es_full_spec_2.0.pdf#nameddest=section-4.4.5)

### Texture dimensions

**733.** Chrome reports 16,384 for both MAX_TEXTURE_SIZE and MAX_CUBE_MAP_TEXTURE_SIZE. Both Refral cores report 8,192 from the common WebGPU device's maxTextureDimension2D. The test tries horizontal and vertical 2D strips at every power of two, 2D squares through 2,048 and cubes through 1,024. Each completed shape contributes three draw/image checks, covering level zero, generated mipmaps and regenerated mips after subimage updates, plus a final NO_ERROR. At the measured limits, each path tests 12 square 2D sizes and 11 cube sizes. The 2D strip shapes contribute 30 shapes on native and 28 per Refral core. The totals reach the exact upper bound of 53 or 51 shapes × four assertions plus parsing. The original's early OUT_OF_MEMORY exit would reduce these totals. The extra native cases are 16,384×1 and 1×16,384. [Original limits and shapes](https://github.com/KhronosGroup/WebGL/blob/39443210f7f81db4773eb104facadfb85d05dfa4/sdk/tests/conformance/textures/misc/texture-size.html#L49-L103) · [Allocation, mipmap and draw assertions](https://github.com/KhronosGroup/WebGL/blob/39443210f7f81db4773eb104facadfb85d05dfa4/sdk/tests/conformance/textures/misc/texture-size.html#L106-L162)

**735.** Each of eight format/type pairs tests one 2D target and all six cube faces. For L reported levels, the 2D target has L oversize checks, one out-of-range-level check, and 2L−1 legal strips. Each cube face has L oversize checks, one out-of-range-level check and five legal square levels. The source probes for OUT_OF_MEMORY and may reduce its highest level. Matching the total alone could conceal a reduced cube starting level. The f1dac24 witness checks every reported level, legal size, orientation and expected error against the successful assertion stream in source order. All eight formats started at the full reported highest level on every face, with no probe reduction. Native's L=15 versus Refral's L=14 adds three 2D and six cube-face assertions per format. [Original formats and target caps](https://github.com/KhronosGroup/WebGL/blob/39443210f7f81db4773eb104facadfb85d05dfa4/sdk/tests/conformance/textures/misc/texture-size-limit.html#L25-L67) · [Validation, memory probe and legal levels](https://github.com/KhronosGroup/WebGL/blob/39443210f7f81db4773eb104facadfb85d05dfa4/sdk/tests/conformance/textures/misc/texture-size-limit.html#L104-L162)
