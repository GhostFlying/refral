# SVG texture uploads with zero dimensions

The pinned WebGL1 Texture Upload Width and Height rule uses the HTMLImageElement width and height of decoded SVG images. The original tex-image-svg-image-no-natural-width-and-height.html also checks the next 1x1 update against the initialized destination and expects INVALID_VALUE. Native records 13/0 and both selected cores 11/2. Cover zero and positive dimensions, definition and partial update, and unchanged state on rejected writes.

This task owns DOM image extent extraction and the core validation of an empty defined image if a three-way trace identifies those modules. First observe native DOM/image dimensions, successful zero-sized texture definition, an absent image level, rejected uploads and the subsequent update. Keep raster images with CSS sizing and broken image sources distinguishable. Run the original in all three backends, shared DOM regression and affected deterministic checks. Preserve raw results in artifacts/conformance/campaign/svg-size.

## Decision and pinned reproduction

The SVG has a viewBox and no explicit width or height. Headless Chrome 158.0.8127.36 reported element and natural dimensions of 150 by 150. Explicit element sizing to 100 by 100 succeeded and all original color checks passed. On the implicit image both native upload overloads reported INVALID_VALUE. In the subimage branch the script had first allocated a valid 150-by-150 texture with null data. Its next 1-by-1 typed update returned INVALID_VALUE natively and succeeded on the two selected cores. In the definition branch the selected cores returned INVALID_OPERATION for the next update of an undefined level. Native returned INVALID_VALUE for an existing empty level. The standalone probe distinguishes an absent level (INVALID_OPERATION) from a defined zero-size level (INVALID_VALUE).

The matching Chromium source calls TexImage2D with 0 by 0 for either overload and then generates INVALID_VALUE. The official script consumes that error before its next assertion. GLES 2.0 §2.5 specifies that ordinary error-generating commands are ignored. A failed subimage update therefore preserves the existing level. The user chose to retain this behavior and the original case’s actual failure. Resolution of the assertion requires agreement upstream on source sizing and the expected post-error state for a previously allocated level. The original remains in the denominator. The public state regression reads the initialized level after the failed SVG subimage call, updates the same texel and reads it again. The native control records the newly incomplete attachment. Probe metadata, counters and raw page images are in artifacts/conformance/campaign/svg-size.

The unmodified original replayed at 13/0 native and 11/2 on each core. The focused public state regression passed all three expected paths. Both cores read back [32,64,96,255] after the rejected SVG, then successfully overwrote it with [255,0,0,255]. Native reported an incomplete attachment and rejected the follow-up update.
