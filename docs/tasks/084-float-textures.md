# Float texture sampling in WebGL 1

Implement the ratified OES_texture_float sampling extension on top of task 069 context restoration and task 083 extension activation. Support FLOAT in texImage2D and texSubImage2D for the five WebGL1 base formats and supported DOM sources. Keep nullable allocations zero-initialized; verify typed view identity, alignment, channel expansion, source conversion and owned bytes for subupdates. Preserve the full floating-point values through the Rust resource transport, common host and actual shader sampling, including alpha one for formats lacking alpha. FLOAT render targets and float linear filtering are optional capabilities with their own extensions. In the initial sample-only implementation reject incomplete float attachments and substitute the incomplete-texture result when linear filtering is requested. Check mip initialization, CubeMap storage and disabled/reenabled extension state after restoration. Keep existing WebGL1 APIs and test sources.

Use pinned OES_texture_float, required WebGL1 texture semantics and the upstream oes-texture-float, float DOM uploads, and OffscreenCanvas context-lost-restored Window/Worker originals. The selected cores own validation and texture completeness; the adapter preserves float payloads and the BrowserHost selects a compatible GPU texture and binding layout. Run deterministic and actual-Wasm coverage and focused headless three-way original files, recording actual assertion counts, GPU errors, pixels and optional extension branches. [Ratified extension](https://github.com/KhronosGroup/WebGL/blob/39443210f7f81db4773eb104facadfb85d05dfa4/extensions/OES_texture_float/extension.xml)

HTML context restoration advanced from 53 to 57 assertions in each core, matching native. Offscreen restoration changed from 6/1 to 7/0 in Window and 1/1 to 2/0 in the dedicated Worker. The original Canvas/ImageData/image float-source files executed 493/227/123 passing assertions on all paths. Video executed 27 on each selected core and 51 on native. The base float original executed 32 in each core and 119 natively; the float-linear original executed 66 in each core and 97 natively. The cores intentionally expose nearest FLOAT sampling. Native also exercises its optional color-renderable and linear-float capabilities.

Both selected-core public tests passed on the same build. A single program switches a cube and a 2D sampler between RGBA32F and normalized allocation, checks selective filter incompleteness, builds cube mip levels, and reads back negative and above-10000 values from owned float uploads.
