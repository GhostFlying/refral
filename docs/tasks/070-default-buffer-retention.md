# Default framebuffer retention

The WebGL1 drawing buffer is initialized after it has been composited when preserveDrawingBuffer is false. The request defaults to false. GLES clear color, masks and scissor state remain unchanged. A preserved drawing buffer retains color, depth and stencil. An off-document surface with no compositor consumer should retain its contents across animation frames.

Probe the visible and detached canvas across rendering updates under headless Chrome. Inspect the WebGPU current-texture lifetime and the behavior of direct synchronous DOM consumers and GL readback. Use an observed rendering boundary for the default target. FBO storage and rendering-state ownership remain with the existing modules. Honour explicit true/false in both public factories. If a browser observation cannot be implemented through the available APIs, keep the specific original outcome for audit.

Run the original buffer-offscreen-test, buffer-preserve-test, context-attribute-preserve-drawing-buffer and webgl-multi-draw files as all three backends. Verify initial and subsequent frames, caller masks, both attribute requests, and detached surfaces. Use the shared headless GPU window. Any transferToImageBitmap reset is coordinated with task 068.

The first implementation matched all canonical clear/preserve operations in buffer-offscreen-test and buffer-preserve-test, plus the applicable multi-draw branch. Direct Canvas2D copies after five frames revealed that Chrome returned transparent black from an opaque WebGPU canvas after compositing; a preserved canonical RGBA8 texture still held red. The same standalone probe on three swap-chain formats reproduced this. The Chrome-native WebGL control returned opaque black for discard and red for the preserved canvas. An ImageBitmapRenderingContext consuming a private GPU canvas snapshot retained the red pixel in all six format/alpha combinations. Try this surface for explicitly preserved content, then verify sizing, transfer, low alpha, same-task and five-frame reads. Evidence is under artifacts/conformance/campaign/default-retention.

On the integrated worker/lifecycle build the original OffscreenCanvas bitmap transfer now passed all 241 assertions on each of the three paths, including the 24 previously failing attribute checks. Both cores also passed the 9 off-document buffer, 29 preserve-buffer, 6 antialias-selection, 44 lifecycle and 85 presentation-alpha assertions. The hardware full engineering suite passed 169/169 in headless Chrome, and 51 actual-Wasm checks passed. Per-file results and screenshots are under `artifacts/conformance/campaign/retention-worker-integration`.

Two discard-mode differences remain. After five composites Chrome 158's opaque WebGPU canvas supplied transparent black to an external Canvas2D drawImage, where the WebGL original expects opaque black. A transferred OffscreenCanvas retained the canonical color on readPixels after its placeholder was composited. The standalone control retains color across frames natively, so resetting every OffscreenCanvas per frame would break it. Hardware probes for standalone and transferred surfaces, bitmap presentation, image copy and texture lifetime are under `artifacts/conformance/campaign/default-retention`. The two originals remain recorded as failures.
