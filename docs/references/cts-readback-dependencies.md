### Framebuffer attachment paths

- `testFramebufferRequiredCombinations` requires RGBA texture color alone, color+depth16 and color+depth-stencil completeness, and checks framebuffer-dependent component bits.
- `testAttachment` checks invalid attachment combinations with clear and readPixels returning INVALID_FRAMEBUFFER_OPERATION. `testAttachments` checks conflicting depth/stencil attachment combinations and component bits.
- `testDepthStencilDepthStencil` alternates depth16 and depth-stencil attachments, deletes or detaches the second attachment, then draws twice with depth LESS and reads the retained green result before and after depth clear. It requires correct attachment restoration and initial zeroed storage.
- `checkValidColorDepthCombination` probes RGBA4 color with depth16, then depth-stencil. Its successful path runs the subsequent completeness/error tests.
- `testUsingIncompleteFramebuffer` checks dimension mismatch, missing attachments and zero-sized attachments. Its nested `testRenderingAndReading` expects INVALID_FRAMEBUFFER_OPERATION from draw/read/clear and allows INVALID_FRAMEBUFFER_OPERATION or INVALID_OPERATION from each copy operation.
- `testReadingFromMissingAttachment` probes depth-only, then depth-stencil-only FBO completeness. A complete color-missing FBO must reject readPixels, copyTexImage2D and copyTexSubImage2D with INVALID_OPERATION. It returns when both combinations are unsupported.
- `testFramebufferIncompleteAttachment`, `testFramebufferIncompleteMissingAttachment`, `testFramebufferIncompleteDimensions` and `testBindRenderbufferBeforeFramebufferAttach` contain state/query/error assertions. Their inclusion in the original HTML also executes its format/render/read paths.

These functions use framebuffer storage, completeness and error behavior. The file has no stencilFunc/stencilOp draw path. Copy commands in this file are expected to fail, so its acceptance needs their validation and errors while successful framebuffer-to-texture copying belongs to separate coverage.
