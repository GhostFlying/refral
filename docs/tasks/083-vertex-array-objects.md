# OES vertex array objects

Implement OES_vertex_array_object for the public JS and Rust drawing cores. Reuse the existing device, actual draw snapshots, checked object handles and Buffer storage. Vertex array binding, element-buffer binding and attribute array descriptors are local to a VAO. ARRAY_BUFFER binding and generic attribute values remain context-global. OES_vertex_array_object requires buffers marked for deletion to detach from the active VAO while retaining their storage through references from other VAOs. Deleting the currently bound VAO rebinds the default. Extension support is discoverable, while its binding query is legal only after successful getExtension. A lost or obsolete extension remains inert after restoration and re-enabling creates a new extension object.

Dependencies are task 069 context loss, task 068 prepared Rust contexts and the pinned original extension and WebGL1 manifest. Own the related facade, logical handle, JS and Rust vertex attributes and buffer references, focused tests, spec mapping, and task evidence. Implement state/lifetime in each core and use a shared fixture plus the unchanged oes-vertex-array-object.html (including real draw and deleted-buffer checks), HTML/Offscreen loss and restoration cases in headless three-way Chrome. Run pnpm check, actual-Wasm and deployment-compatible builds. Offscreen restoration additionally requires the independent OES_texture_float extension; keep its actual result. [Ratified WebGL extension](https://github.com/KhronosGroup/WebGL/blob/39443210f7f81db4773eb104facadfb85d05dfa4/extensions/OES_vertex_array_object/extension.xml)

Before enabling the extension both implementations completed the original extension file with 5 passing availability checks. The first implemented run executed all 93 assertions on Chrome native and each selected core, including the upstream draw and retained-buffer pixel comparisons. Both selected OffscreenCanvas loss files now complete (2/0 in Window, 5/0 in Worker). HTML loss passes 189/0 for all backends, and HTML restoration executes 53/0 for both cores versus Chrome's 57/0. Offscreen Window/Worker restoration still fails one assertion each in the helper requiring OES_texture_float. Public headless tests also exercise fresh extension visibility after restore, a retained old extension, and foreign-generation object rejection. The Rust capability is explicit, so an older compatible custom module does not advertise this extension. Raw baseline, probe and final original evidence is in artifacts/conformance/campaign/vao-baseline, vertex-arrays-probe and vertex-arrays-on-main.
