# CubeMap and original DOM texture CTS

## Implementation

Tasks034–037 add level-zero CubeMap sampling to both actual semantic cores through the shared facade, compiler and BrowserHost. First binding fixes the texture target. Each unit retains independent 2D and cube bindings. Each face owns its dimensions, logical format, storage generation and content version. Complete draw snapshots contain six canonical images and copied sampling parameters. BrowserHost materializes and caches a six-layer cube texture against all six versions, with queued-resource retirement.

The private Rust resource capability is3 alongside ABI3/readback1/DOM2. Every texture version carries image target and level, and sampled bindings carry dimension and presence. Pre-execution operation capacity covers six-face retirement. Old capability2 modules fail before context initialization and provide rebuild guidance. [Image and protocol decision](../adr/009-texture-image-subresources.md)

The pinned ANGLE WGSL backend has two additional adaptations. Implicit vertex texture sampling uses explicit base LOD. The original CTS gl_FragData array remains in private pipeline state, with scalar location outputs and end-of-entry-point element copies. The exact original shader, array reads, early returns, index limits and gl_FragColor exclusivity have regressions. Source strings retain their original contents.

## Scope and next dependencies

Accepted cube sampling uses level zero, scalar samplerCube, five UNSIGNED_BYTE logical formats for typed/null input and RGBA DOM sources. Nonzero levels, mipmap generation, packed types, cube framebuffer attachments, additional DOM encodings and context restoration retain separate compatibility tasks. Legal cube framebuffer attachments produce the declared profile diagnostic. Texture2D framebuffer behavior retains its accepted profile.

The existing HTMLImage fidelity path uses the private native WebGL pixel extractor accepted in ADR008. The stage uses that source path for cube faces. Native source-context coordination across independently loaded modules/realms remains in the prior DOM follow-up scope. [DOM extraction decision](../adr/008-dom-image-extraction.md)

Subsequent compatibility tasks follow the residual prerequisites in fixtures.lock.json, including packed RGBA uploads, mipmaps/copy-texture validation and renderbuffer formats. Buffer-version caching has its own measurement and regression scope in the roadmap.
