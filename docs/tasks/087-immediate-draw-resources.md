# Reuse uniform resources for immediately submitted draws

After synchronous canvas publication, every default draw has its own GPU submission. The executor still creates two uniform buffers and a bind group for each draw, even when the same program is used repeatedly. The pinned many-draw-calls page performs 505,000 draws over 100 rendering updates. The prior long-running selected sweep stopped responding in that file. A standalone measurement will separate submit, bind group and allocation counts from actual CPU time.

Reuse per-program uniform buffers only across draws whose prior reads have already been submitted. All unsubmitted FBO draws must have independent snapshots. Keep queue ordering, program generations, both shader stages, cross-target draws and existing DOM observation. Share the empty texture bind group for programs with no samplers. Verify actual before/after resource counts and pixels with a bounded uniform workload, a same-task default/FBO sequence, the full engineering suite, and the original suite independently of timing. Use headless Chrome and actual Rust/Wasm.

On Apple Metal, 128 changing-uniform draws at 64×64 needed 257 bind-group creations per measured batch before this change and 2 after it. The 128 submissions and uploaded byte counts matched. Four batches warmed the context. For 18 recorded batches the CPU time through explicit flush had JS median/p95 2.05/2.3 ms before and 1.60/2.7 ms after, Rust 4.60/5.3 ms before and 4.30/5.5 ms after, and native 0.0/0.1 ms on both. Completed-image readback and the GPU fence were outside the interval. This verifies reduced allocation and exposes variation in the upper tail. It does not establish an original-file pass. Samples, environment and pixel checks are under artifacts/conformance/campaign/immediate-uniforms.
