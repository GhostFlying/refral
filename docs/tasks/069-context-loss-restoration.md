# Simulated context loss and restoration

## Goal and specification

Implement the ratified WEBGL_lose_context extension for public JS and Rust contexts with one stable facade, context attributes and extension object. The first simulated loss invalidates that generation immediately and queues a cancelable event. Restoring requires that the dispatched event completed with preventDefault. A valid restore request queues rebuilding fresh GL state, object namespaces and GPU resources before firing webglcontextrestored. Repeated invalid calls generate INVALID_OPERATION even during loss. Real device loss is independently observable and cannot be restored through the simulation extension. Other contexts that share the physical device retain their state. [Pinned extension specification](https://github.com/KhronosGroup/WebGL/blob/39443210f7f81db4773eb104facadfb85d05dfa4/extensions/WEBGL_lose_context/extension.xml)

## Plan and dependencies

Reuse the drawing cores' existing lost-state behavior, shared compiler and independently owned BrowserHost resources. Keep the public async factory and synchronous GL calls. Reinitialize a selected semantic core with a new logical context id on restoration so retained old wrappers cannot alias new slots. The facade owns event delivery and the extension object. Each generation owns concrete resources, compiler namespaces and its buffer/program/texture wrapper registries. The harness's prepared contexts may share a GPUDevice: retiring one generation releases only its own resources. Map any newly entered lost-state branches to original assertions before correcting their GL behavior.

The task owns the facade factory/lifecycle and its direct regression, selected core loss behavior where required, spec/support records and the relevant case evidence. Tasks 064 and 068 provide worker contexts and tracked OffscreenCanvas, and task 070 supplies the requested preserveDrawingBuffer profile independently. OES_vertex_array_object and other optional extensions are reported according to actual availability.

## Acceptance

- Run TypeScript, deterministic unit/native and adapter checks. Verify immediate and event-time lost state, canceled/uncanceled restore, duplicate requests, extension identity, unchanged peer context, restored default state, prior generation handles, and a fresh draw in headless Chrome for JS/Rust.
- Run the pinned original context-lost/context-lost-restored documents on HTMLCanvas and OffscreenCanvas (Window/Worker), plus the formerly conditional attribute/uniform lookup cases. Record exact original assertions, branches, worker provenance, screenshots, any genuine remaining dependencies and Chrome deviations.

The dedicated public regression exercises actual Wasm and GPU submission. A loss and restore cycle invalidates old handles, restores default state, keeps the extension object and public facade, and renders a green pixel while another context on the same device retains its red pixel. A physical device-loss case verifies newly created shader/buffer wrappers remain invalid. The method/attribute lookup originals require the JS name checks introduced in task 054 on the integration branch. Offscreen loss helpers additionally require OES_vertex_array_object; their restoration helpers also require OES_texture_float, returning false when either helper returns undefined for an absent optional extension. These dependencies retain their original assertions.

The final targeted browser run used the task 054 name-validation fix already integrated on main and a locally rebuilt actual Rust module. HTML context loss finished 183/0 and restoration finished 44/0 for each selected core; Chrome native finished 189/0 and 57/0. Both location-error files executed the extension branches and passed 118/0 each on all three backends. The four OffscreenCanvas original files pass on Chrome. Each reports one failure on both selected cores: the loss helper explicitly requires OES_vertex_array_object, and the restoration helper additionally treats an absent OES_texture_float as a failed result. Those optional extensions must implement their own behavior before these four originals can pass. No assertion or extension probe was bypassed. Public headless lifecycle tests passed 3/3, including restoration, old wrappers and an unaffected peer on a real shared GPU device. Actual Wasm tests passed 47/47. Artifacts are under artifacts/conformance/campaign/context-lifecycle with per-case screenshots, full original counts, GPU details and public.log.
